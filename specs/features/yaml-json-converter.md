# YAML/JSON 互转工具

## 1. 产品概述

一个**双向实时转换**的 YAML ↔ JSON 工具，采用左右分栏布局，左侧编辑 YAML、右侧对应 JSON，任一端修改后另一端自动实时转换刷新。面向日常处理 Kubernetes 配置、OpenAPI/Swagger 文档、CI/CD 配置文件（GitHub Actions、GitLab CI 等）等场景的开发者。

---

## 2. 核心流程

用户打开 YAML/JSON 互转页面，看到左右双栏编辑器（左 YAML / 右 JSON）。用户可以在任意一侧粘贴或编辑内容，另一侧自动实时完成格式转换并刷新显示。用户也可以从本地导入文件，或将转换结果导出为文件。当任一侧出现语法错误时，另一侧保留上一次有效的转换结果，并在页面顶部显示明确的错误信息。

---

## 3. 验收标准

### Happy Path（正常流程）

**AC-001** — 页面布局  
Given 用户进入 YAML/JSON 互转页面，Then 页面呈现左右两栏布局，左侧为 YAML 编辑器（YAML 语法高亮），右侧为 JSON 编辑器（JSON 语法高亮），两侧均使用 Monaco Editor。

**AC-002** — YAML → JSON 实时转换  
Given 用户在左侧 YAML 编辑器中输入有效的 YAML 内容，When 用户输入或粘贴 YAML，Then 右侧 JSON 编辑器**自动实时**显示对应的 JSON 内容，无需用户手动触发转换。

**AC-003** — JSON → YAML 实时转换  
Given 用户在右侧 JSON 编辑器中输入有效的 JSON 内容，When 用户输入或粘贴 JSON，Then 左侧 YAML 编辑器**自动实时**显示对应的 YAML 内容，无需用户手动触发转换。

**AC-004** — 从文件导入  
Given 用户在 YAML/JSON 互转页面，When 用户点击"导入"按钮并选择一个 YAML（.yaml/.yml）或 JSON（.json）文件，Then 文件内容被加载到对应的编辑器中，并根据文件扩展名自动填充到左侧（YAML）或右侧（JSON），另一侧自动完成转换。

**AC-005** — 导出为文件  
Given 用户已完成 YAML/JSON 转换，When 用户点击"导出"按钮，Then 弹窗让用户选择导出格式（YAML 或 JSON），选择后下载对应格式的文件到本地。

**AC-006** — 多文档 YAML 转 JSON  
Given 左侧 YAML 编辑器中包含由 `---` 分隔的多个 YAML 文档，When 右侧自动转换，Then 右侧 JSON 输出为 JSON 数组，数组中的每个元素对应一个 YAML 文档。

**AC-007** — JSON 数组转多文档 YAML  
Given 右侧 JSON 编辑器中包含一个 JSON 数组，When 左侧自动转换，Then 左侧 YAML 输出用 `---` 分隔的多文档格式，数组中的每个元素作为一个独立文档。

**AC-008** — YAML 锚点支持  
Given 左侧 YAML 编辑器中包含使用锚点（`&anchor`）和别名（`*anchor`）的 YAML 内容，When 右侧自动转换，Then 右侧正确展现锚点展开后的完整 JSON 结构。

### Edge & Error Cases（边界和异常）

**AC-009** — YAML 语法错误时保留上次 JSON 结果  
Given 左侧 YAML 编辑器中已有有效的 YAML 内容且右侧已显示对应的 JSON，When 用户在左侧输入导致 YAML 语法错误，Then 右侧 JSON **不清空**，保留上一次有效的转换结果，同时页面显示错误提示。

**AC-010** — JSON 语法错误时保留上次 YAML 结果  
Given 右侧 JSON 编辑器中已有有效的 JSON 内容且左侧已显示对应的 YAML，When 用户在右侧输入导致 JSON 语法错误，Then 左侧 YAML **不清空**，保留上一次有效的转换结果，同时页面显示错误提示。

**AC-011** — 错误提示位置与内容  
Given 任一侧编辑器出现语法错误，Then 在页面顶部或状态栏显示红色错误提示，内容包括：错误类型、错误位置（行号/列号）和具体错误原因。

**AC-012** — 空内容处理  
Given 左侧 YAML 编辑器内容被清空，Then 右侧 JSON 编辑器同步清空。反之亦然，右侧 JSON 内容清空时左侧 YAML 同步清空。

**AC-013** — 超大文件处理  
Given 用户粘贴或导入的内容超过 1MB，Then 页面显示"内容过大，建议分段处理"的提醒，不阻塞页面响应。

### Business Rules（业务规则）

**AC-014** — 转换方向自动检测  
Given 用户在任一侧编辑器中输入内容，Then 系统根据内容所在的编辑器确定转换方向：左侧内容变更 → 向右转换（YAML → JSON），右侧内容变更 → 向左转换（JSON → YAML），确保不会形成双向循环转换。

**AC-015** — 转换触发时机  
Given 用户在编辑器中输入，Then 转换在用户停止输入 500ms（防抖）后触发，避免每次按键都执行转换。

**AC-016** — 编辑器语言模式  
Given 页面加载完成，Then 左侧 Monaco Editor 的语言模式设置为 YAML，右侧设置为 JSON，提供对应的关键字高亮和语法提示。

## 4. 范围界定

### 本次做
- 左右双栏 YAML ↔ JSON 实时转换核心功能
- 从文件导入（YAML/JSON）
- 导出为文件（YAML/JSON）
- 多文档 YAML（`---` 分隔）支持
- YAML 锚点/别名支持
- 语法错误时的保留上次结果和错误提示
- Monaco Editor 编辑体验（YAML/JSON 语法高亮）

### 本次不做
- 代码/树状/表单/预览/表格等多视角查看（JSON 编辑器已提供，不重复）
- 多 Tab 支持（一次只处理一个文件）
- 批量文件转换
- YAML 1.1/1.2 版本选择
- 自定义缩进空格数（默认 2 空格）
- 历史记录/撤销栈跨编辑器同步
- 云端存储/分享
